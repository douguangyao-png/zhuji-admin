# 开发指南

筑基是一个 React 管理后台框架。这份指南讲怎么在它上面开发自己的系统；功能总览和快速开始见根目录的 README，安全相关见《安全说明》，后端接口见《接口约定》。

## 1. 改名与配置

复制工程后先改 `src/app.config.ts`：产品名称（默认 `xxx管理系统`）、使用单位、存储键前缀、接口前缀、备份文件名前缀；再改 `index.html` 的 `<title>` 和 `package.json` 的名称。运行时的产品名称和使用单位以「系统管理 › 基础配置」为准。

## 2. 一个模块由什么组成

`features/<键>/` 下五个文件，照 `features/example` 写：

| 文件 | 内容 |
| --- | --- |
| `types.ts` | 数据结构、状态、字段长度上限（前端 `maxLength` 和模拟后端共用） |
| `api.ts` | 页面调用的接口函数，只经 `http()`，不直接读模拟层 |
| `mock.ts` | 模拟后端：接口、种子数据、审批流和字典的登记、首页待办、单号链接；规则要与真实后端一致 |
| `*Page.tsx` | 页面 |
| `index.tsx` | `ModuleDef`：菜单、路由、首页卡片、模块开关键 |

用 `npm run new:module <键> <名称>` 生成，不要手工复制。生成后在 `app/modules.ts` 里确认顺序，在「系统管理 › 角色权限」里给角色勾上新权限点。

## 3. 约定

- 页面只通过各模块的 `api.ts` 取数改数；接真实后端时只换 `http()` 的实现。
- 按钮点击后显示加载状态并禁止连点；所有输入框限长，与后端校验和列宽一致；所有删除先确认（删除按钮用 `btn-ds`，点击前走 `deleteConfirm`）。
- 按钮都是「图标 + 文字」，`test/buttons.test.ts` 会检查。
- 权限用 `can('模块:动作')` 和 `<Can>`；号码类字段用 `<Masked>`；日志用 `log`。详见《安全说明》第 5 节。
- 模拟数据用固定种子，日期相对今天生成；时间用 `lib/time.ts`，不直接 `new Date()`。
- 界面、注释、测试名用中文，文案写清对象、数字和动作。

## 4. 测试与检查

| 命令 | 说明 |
| --- | --- |
| `npm run typecheck` | 类型检查 |
| `npm test` | vitest；`src/test/routes.test.tsx` 用三个账号打开每个菜单，页面抛错或有 React 警告就失败，新模块自动纳入 |
| `npm run check:clean` | 扫描残留名称；两份 README 的二级标题数量要一致 |
| `npm run check:api` | 页面用到的接口必须写进《接口约定》 |
| `VITE_API=server npm run build` | 连真实后端的构建，产物里不应有模拟层 |

测试里用 `openApp(路径, 用户id)` 打开页面，`beforeEach(freshDb)` 恢复演示数据。演示账号：U01 系统管理员，U02 业务管理员，U03 部门负责人，U04、U05 普通用户。

## 5. 发版

在 `features/help/releases.ts` 最前面加一条版本说明，在 `guide.ts` 里补操作说明；`guide.test.tsx` 会检查里面的链接都指向存在的页面、步骤权限与菜单权限一致。

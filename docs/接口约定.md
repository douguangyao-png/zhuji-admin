# 接口约定

框架默认在浏览器里跑模拟后端（`src/api/mock/`），用 `VITE_API=server` 构建时所有请求发到真实后端。本文列出框架页面用到的全部接口，后端按这里实现即可让框架页面全部可用。`npm run check:api` 会比对页面代码和本文，页面新用了接口而这里没写时检查失败。

## 1. 通用规则

| 项 | 约定 |
| --- | --- |
| 前缀 | `src/app.config.ts` 的 `apiBase`，默认 `./api/v1`，相对页面地址；下表路径都省略前缀 |
| 格式 | 请求、响应都是 JSON（UTF-8）；上传文件用 `multipart/form-data`，备份包上传用 `application/zip` |
| 响应包 | `{ "code": 0, "message": "ok", "data": … }`；`code` 不为 0 或 HTTP 状态不是 2xx 时，页面显示 `message` |
| 状态码 | 400 参数不对；401 未登录、登录过期或被踢下线（页面回登录页，`/auth/*` 除外）；403 没有权限；404 不存在；409 重复；422 业务校验不通过，`message` 写给用户看 |
| 登录态 | 服务端写 HttpOnly Cookie，前端不存令牌；浏览器里只记用户 id 和会话号（见 `docs/安全说明.md`） |
| 分页 | 查询参数 `page`（从 1 起）、`size`（最大 500）；返回 `{ items, total, page, size }` |
| 多选筛选 | 同一参数用英文逗号连接，如 `unitId=D01,D02` |
| 时间 | `yyyy-MM-dd HH:mm:ss`，本地时区；日期 `yyyy-MM-dd` |
| 防重复提交 | 前端对同一个写请求在返回前不再发第二次；后端对关键写操作仍应做幂等或唯一约束 |
| 字段长度 | 前端 `maxLength` 与后端校验、列宽一致，超长返回 422「X 最多 N 个字」 |
| 留痕 | 增删改、审批、导入导出、配置变更写操作日志；登录相关写登录日志；删除写删除记录，可恢复；日志只增不改不删 |

### 1.1 密码传输（SM2）

登录、改密码、物理删除时，密码字段不明文传输：

1. 前端 `GET /auth/pubkey` 取 `{ kid, publicKey, now }`（SM2 公钥十六进制；`now` 为服务器毫秒时间，用来校正本机时钟）。
2. 把 `{ ...密码字段, n: 16 字节随机数十六进制, t: 毫秒时间 }` 序列化后用 SM2 加密，请求体带 `{ kid, enc }` 代替明文字段。
3. 服务端解密后校验 `t` 在窗口内、`n` 没用过；公钥换过或时间对不上时返回 422，`data` 带 `{ "pubkeyExpired": true }`，前端重新取公钥再发一次。

服务端回给浏览器的密码（重置后的默认密码）反过来：请求体带临时公钥 `publicKey`，服务端返回 `{ enc }`。

### 1.2 权限与数据范围

接口按权限点校验，权限点目录见 `src/api/perms.ts`；角色权限含 `*` 时全部放行。带 `/import` 的提交要 `op:import`，以 `/export` 结尾的下载要 `op:export`。数据范围（全部、本部门及下级、本部门、本人、自定义组织）由各业务列表接口按当前用户的角色合并计算，**前端的菜单和按钮隐藏只是提示，越权请求必须由后端拒绝（403）**。

### 1.3 登录会话

登录成功返回用户，另带 `sid`（会话号）。安全策略 `sessionPolicy=kick` 时，同账号再次登录后旧会话的请求返回 401，并记一条「被踢下线」登录日志；`allow` 时多处同时在线。锁定、空闲超时的参数见 `PUT /settings`，锁定和并发登录由后端执行。

# 安全说明

**前端框架只能提示，所有权限和校验必须以后端为准。** 本文写清楚框架做了什么、没做什么，以及使用方部署时必须自己做的事。它不是安全认证或等级保护的结论，也不保证符合任何标准。

## 1. 框架做了什么

| 方面 | 做法 | 在哪里 |
| --- | --- | --- |
| 密码传输 | 登录、改密码、物理删除时密码用服务端 SM2 公钥加密，带一次性随机数和时间戳防重放 | `src/api/sm2.ts`，规则见接口约定 1.1 |
| 登录保护 | 滑块验证码（总是 / 密码错 N 次后 / 关闭）；连续输错达到次数锁定若干分钟；错误提示不区分账号不存在还是密码错 | `src/api/mock/captcha.ts`、`core.ts` |
| 密码规则 | 最短长度、字符类别、不能含空格、不能包含工号或登录名、不能与最近几次相同、有效天数 | `src/lib/password.ts` |
| 强制改密码 | 新建账号、管理员重置后的账号首次登录必须改；默认密码只能忽略有限次数 | `src/app/ChangePassword.tsx` |

| 并发登录 | 可配置允许多处在线或踢掉旧会话（旧会话请求回 401） | 安全策略页、`src/api/mock/session.ts` |

## 2. 框架没做什么

- 不做任何后端校验。模拟后端只为演示，里面的锁定、会话、权限判断**不是安全机制**。
- 不做服务端会话管理、令牌签发与刷新、密码哈希存储、验证码的真正防绕过——这些由后端实现。
- 水印、脱敏、隐藏按钮和菜单都**防不住**有意的截图、拍照、抓包或改页面。
- 不提供 HTTPS、WAF、限流、防爆破、入侵检测、数据库加密、密钥管理、备份加密。
- 不做病毒扫描、内容审核；不保证第三方依赖没有漏洞（请自行跑依赖审计并及时升级）。
- 不提供等级保护、行业合规、个人信息保护方面的任何结论或材料。

## 3. 令牌与会话

- 现状：浏览器里只存用户 id 和会话号（`localStorage`），它们**不是凭证**，改了也只会让界面显示成另一个人，后端仍按 Cookie 识别身份。
- 推荐：登录凭证由后端写 `HttpOnly; Secure; SameSite=Lax`（或 Strict）的 Cookie，前端读不到，JS 注入也偷不走。不要把令牌放进 `localStorage`、`sessionStorage` 或 URL。
- 使用 Cookie 时写请求要防 CSRF：校验 `Origin` / `Referer`，或加自定义头与 CSRF 令牌。
- 单点登录的令牌只在跳转时放在地址里一次，页面取到后立即用 `history.replaceState` 去掉（`src/main.tsx`）。

## 4. 使用方部署时必须自己做的事

1. **全站 HTTPS**，并开启 HSTS；内网部署同样建议。
2. **后端校验一切**：认证、每个接口的权限点、数据范围、字段长度与格式、重复提交、文件类型与大小、SQL 与命令注入防护。前端已有的校验后端必须再做一遍。
3. **后端执行**连续输错锁定、密码规则、强制改密、会话超时、并发登录策略、验证码校验；密码只存加盐哈希（推荐 SM3 或 bcrypt / argon2）。
4. **敏感字段在后端脱敏**后再返回；需要看全号的场景由后端单独授权，不要把明文发给前端再靠界面遮住。
5. **日志**：后端落库操作日志和登录日志，只增不改不删，保留期按你方要求；`/client-logs` 要限频、限长、再脱敏。
6. **响应头**：按第 6 节配置 nginx；上线后用浏览器开发者工具确认生效。
7. **依赖与构建**：定期 `npm audit` 并升级；用 `VITE_API=server` 构建，确认产物不含模拟层；不要把 `node_modules`、源码映射、`.env` 发布出去。
8. **合规**：等级保护、个人信息保护、数据出境、密码应用等要求由使用方评估和落实，本框架不代为承担。

## 5. 前端约定（写新模块时）

- 权限：菜单项写 `perm`；按钮和字段用 `can('模块:动作')` 或 `<Can perm=…>`；接口同一个权限点后端必须校验。不显示无权限的字段，不要靠 CSS 隐藏。
- 号码类字段用 `<Masked kind="phone|idCard">`，不要自己拼星号。
- 不使用 `dangerouslySetInnerHTML`；必须渲染外来 HTML 或 Markdown 时先过 `sanitizeHtml`。
- 外链加 `target="_blank" rel="noopener noreferrer"`。
- 日志用 `log.debug/info/warn/error`，不要直接 `console.log` 业务数据；传给日志的对象会自动脱敏，但仍不要主动传密码、令牌。
- 数据范围：列表接口按当前用户的角色合并范围后过滤，前端不在本地过滤出「看起来只有自己的数据」。

## 6. 推荐的响应头（nginx）

内容安全策略在构建产物里已有 meta 版本；响应头版本能管得更全（尤其是 `frame-ancestors`，meta 里无效），建议以响应头为准。

```nginx
server {
  listen 443 ssl http2;
  # ssl_certificate / ssl_certificate_key 按你方证书配置

  add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
  add_header X-Content-Type-Options "nosniff" always;
  add_header Referrer-Policy "strict-origin-when-cross-origin" always;
  add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;
  # 不允许被别的站点嵌入；要嵌入到指定站点时把 'none' 换成站点地址
  add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'" always;
  add_header X-Frame-Options "DENY" always;   # 老浏览器兜底，与 frame-ancestors 一致

  location / {
    root /usr/share/nginx/html;
    try_files $uri $uri/ /index.html;
    # 带哈希的静态文件可长期缓存，index.html 不缓存
  }
  location = /index.html { add_header Cache-Control "no-store" always; }
  location /api/ { proxy_pass http://backend; }
}
```

说明：`style-src 'unsafe-inline'` 是因为 React 的 `style` 属性和部分组件用到内联样式；脚本不允许内联。接了企业微信、钉钉等需要额外域名时，在 `connect-src`、`img-src` 里加上具体域名，不要放宽成 `*`。

## 7. 已知限制

- 空闲超时只在浏览器里计时：关掉页面或断网时不会通知后端，后端必须有自己的会话过期。
- 水印是 DOM 元素，开发者工具里可以删掉；要做可追溯的截图防护需要后端配合。
- 内容安全策略的 meta 版本不支持 `frame-ancestors`、`report-uri`。
- 前端错误上报限频为每分钟 10 条，同一条消息一分钟只报一次，可能漏掉重复出现的问题。
